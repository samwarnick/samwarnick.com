As part of my [Lemon Point effort](https://samwarnick.com/blog/lemon-point/), I'm attempting to have clear boundaries on when I work on side projects. The current plan is two weeks on, one week off. I just finished the first two week block, and figured the off week would be a good chance to go over what I've done and maybe what's coming up.
## ScreenCred

To take things more seriously, I moved ScreenCred off of my homegrown deploy system and off of the server in my closet. I want it in a more production ready system. I decided to give [Railway](https://railway.com/) a try. I like that they charge by usage, so it makes it very easy to get into when your apps have near 0 usage like mine. Right now, ScreenCred is calculated to cost about $0.30 a month. However, paying for usage can also be dangerous. There are limits, so it shouldn't go wild, but I'm keeping an eye on it. Railway seems fine overall, but I'm still giving it a try and unsure if it's the best long term solution. I miss using code to set everything up like I had with Deploybot-3000, but I think I can make use of the Railway API to bridge some gaps. It was easy to get things set up since ScreenCred was already containerized. It was also easy to connect several services together. Railway has some AI features, but they are not in your face like some other platforms. But, [Deploybot-3000 is still on my list](https://lemonpoint.net/) of things to maybe get production ready.

With the move, I took the opportunity to clean a few things up.

- Did some load testing and fixed some performance issues.
  - I used [k6](https://k6.io/).
  - One function was `O(n^2)` and is now `O(n)`.
  - I also split the og:image generation into a [separate service](https://github.com/LemonPoint/ScreenCred-Image). This lets me scale it separately from the main app. It is much more resource intensive. Also, by being an API call it prevents it from blocking the rest of the application in case it is running slow.
- With the [iOS app coming back](https://apps.apple.com/us/app/screencred-movie-tv-credits/id1670497275), I needed to add the `apple-app-site-association` file back. That lets universal links and the App Clip work.
- I switched to using `ky` and `zod` instead of pure `fetch`. 
  - `zod` is a good practice for ensuring the data from the API is actually the expected format, not just assuming it is.
  - `ky` has a nice API for using `zod` schemas to automatically parse the response.
  - ```ts
    //BEFORE: Nothing ensures data is actually a PagedResponse
    const response = await fetch('/api/popular', 
      { headers: { 'Content-Type': 'application/json' }
    });
    const data: PagedResponse[] = await response.json();
    //AFTER: ky with zod will throw an error is response does not match schema
    const data = await ky.get('/api/popular').json(PopularResponseSchema);
    ```
- Fixed my error handler to not log and return 404 errors as 500 Internal Server errors with an actual error page.
  - ```ts
    export const handleError: HandleServerError = ({ error, event, status }) => {
      if (status === 500) {
        logger.error('Unhandled error', {
          method:  event.request.method,
          path: event.url.pathname,
          error: error instanceof Error ? error.message : 'Unknown error',
          stack: error instanceof Error ? error.stack : undefined
        });
      }
    
      return {
        message: status === 404 ? 'Not Found' : 'Internal Error'
      };
    };
    ```
## Limits

I started on my first new app. The working title is Limits. The way I'm thinking of it is like a pomodoro timer, but on a weekly level instead of minutes. Like I said, I'm doing two weeks on and then a one week break. I wanted a glanceable way to see where in the schedule I am. Limits provides a menu bar app as well as a widget to show this.
